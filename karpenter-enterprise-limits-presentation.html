WHAT KARPENTER DOES WELL

A strong foundation for node autoscaling

⚡
Fast Provisioning
45-60s from pod pending to node ready. Direct EC2 RunInstances API, no ASG roundtrip. CAS takes 3-4 min for the same.
⚙
Smart Instance Selection
Picks cheapest fitting instance from a broad pool. Not limited to pre-defined node groups like CAS.
📦
Active Consolidation
WhenEmptyOrUnderutilized policy continuously evaluates and consolidates workloads onto fewer nodes.
☁
Native Spot Support
Declarative spot/on-demand in NodePool requirements. Automatic fallback. No separate ASGs needed.

WALL 02 · CONSOLIDATION BREAKS STATEFUL

Consolidation gets switched off

Stateful and long-running workloads can't survive standard eviction. Teams restrict or disable consolidation entirely — efficiency stalls.

STANDARD EVICTION
Pod terminated → restarted on new node
✖ Database connections dropped
✖ JVM cold start (30-60s)
✖ In-flight transactions lost
✖ PVC reattachment latency
✖ Batch jobs restarted from scratch
CONTAINER LIVE MIGRATION (CLM)
Pod moved live — memory, state, TCP preserved
✔ Zero downtime migration
✔ TCP connections preserved
✔ Memory pages transferred live
✔ CRIU checkpoint/restore tech
✔ Forked AWS VPC CNI — IP retained
✔ Graceful fallback to eviction if needed

# Live Controller labels pods automatically:

CRD-FIRST APPROACH

Your NodePools remain the source of truth

Cast AI reads and, when optimization is enabled, modifies Karpenter CRDs to steer provisioning decisions. Your existing resources remain portable. No vendor lock-in.

# Cast AI steers Karpenter via CRD modifications

# Example: RI-aware instance family priority
apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: cast-ai-optimized
spec:
  template:
    spec:
      requirements:
      - key: karpenter.sh/capacity-type
        operator: In
        values: ["spot", "on-demand"]
      - key: karpenter.k8s.aws/instance-family
        operator: In
        values: ["m5", "m6i", "r5", "r6i"]
  limits:
    cpu: "1000"
    memory: 4000Gi
  disruption:
    consolidationPolicy: WhenEmptyOrUnderutilized
    consolidateAfter: 30s
